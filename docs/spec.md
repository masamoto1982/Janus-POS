# Janus-POS 仕様書

現在の実装（`pos/core` と `pos/web`）から書き起こした仕様。実装と食い違う記述を見つけたら、実装を正としてこの文書を直す。

## 1. 概要

Janus-POS は、コンビニエンスストア向けのセミセルフ式 POS レジのシミュレーターである。ブラウザ上で、レジ 2 台・呼び鈴（Bell）3 台・売り場（Item）・お客様の財布（Wallet）を一画面に並べ、買い物から決済、店員呼び出し、店舗の入出金までを再現する。

| 層 | 場所 | 役割 |
| --- | --- | --- |
| コア | `pos/core`（Rust） | 店舗の状態と業務ルールのすべて。決定的な状態機械で、JSON のコマンドを受けて JSON のスナップショットを返す |
| Web UI | `pos/web`（TypeScript + Vite） | スナップショットを HTML に描き、ユーザー操作をコマンドに変えてコアに送る。画面だけの一時状態（開いているテンキー、選んでいるタブなど）以外は持たない |
| 境界 | `pos/core/src/wasm.rs` | `PosSimulator`（`new(seed, registers, bells)`・`restore(saved)`・`dispatch(json)`・`tick(now_ms)`・`snapshot()`・`save()`） |

画面のボタンの押せる・押せないは、コアが返す `actions`（操作ごとの可否と理由）だけで決める。コアは同じ判定関数（`authority::permitted`）でコマンドを検証するので、画面に見えていても操作できないことはあっても、その逆は起きない。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| スタッフ操作モード | 内部名 `staff_operated`。スタッフがスタッフバーコードでログインしているレジ |
| セルフ操作モード | 内部名 `self_operated`。ログインしているスタッフがいないレジ。お客様が登録・キャッシュレス決済をする |
| 店舗処理モード | 店舗メニューを開いている間のヘッダー表示（内部では `menu` が開いている状態） |
| スタッフ側／お客様側 | 1 台のレジに付いた 2 つの画面。内部名 `staff` / `customer` |
| 操作側 | いま操作できる画面（`active_side`）。`null` なら両方 |
| 入金ボックス・出金ボックス | 自動釣銭機の投入口と排出口。スタッフ側に付いている（内部名 `inlet` / `outlet`） |
| 決済端末 | 電子マネー・クレジットカードをかざす端末。お客様側に付いている（内部名 `terminal`） |
| スキャナ | 商品・決済用バーコード・ポイントカードを読む機器。お客様側の決済端末の右に付いている（内部名 `scanner`） |
| Bell | 呼び鈴。据え付け端末・可搬性端末・ストアコンピューター（内部名 `bell`。呼び出しの状態をBellへ送る信号は `signal`） |
| FF | カウンターのファストフード。バーコードを持たず、タブから登録する |
| 明細 | 取引に登録した商品の行（`Line`） |

## 3. 店舗の構成

- レジは 1〜10 台、Bell は 1〜5 台まで作れる（`MAX_REGISTERS`・`MAX_BELLS`）。Web UI はレジ 2 台・Bell 3 台で起動する。
- 乱数の種は起動時刻から取る（`Date.now() & 0xffff`）。乱数は Bell の通信ロスの再現にだけ使う。
- 時刻はシミュレーター内の経過ミリ秒。UI は 100ms ごとに `tick` してスナップショットを取り直し、操作のたびにも `tick` してからコマンドを送る。

読んだバーコードは次の順で振り分ける（`catalog::classify`）。会計画面でも読める。

| --- | --- |

### 3.4 状態の保存

- 店舗の状態（全レジの取引・会計の途中経過・ログイン・呼び出し・現金・Bell の通信状態・販売規則・税率・監査記録・乱数の状態）を JSON にしてブラウザの localStorage（キー `janus-pos-state`）に保存する。買い物は 1 取引 100 点までなので、状態全体でも小さく、毎回まるごと書き換える。
- 保存するのは、コマンドが通ったとき・約 1 秒ごと・ページを離れるとき（`pagehide`）。
- ページを開くと保存された状態から再開する。時計は保存した時点の続きから進み、ページを閉じていた時間は数えない。押し続けていたベルは離した扱いにする。
- 保存形式には版番号（`persist::SCHEMA`）を持たせる。版が違う・壊れている・知らない商品やクーポンやスタッフを含む状態は読まずに捨て、新しい店舗で始める。古い形式からの移行はしない。
- 画面だけの一時状態（開いているテンキー、選んでいるタブ、オーナー認証など）は保存しない。
- 上部の「リセット」は、確認のあと保存された状態を消して最初からやり直す。

## 4. モードと操作権

### 4.1 モード

- モードはログインだけで決まる。スタッフがログインしていればスタッフ操作モード、いなければセルフ操作モード。コマンドを処理するたびに合わせ直す。
- ログインはスタッフバーコードを読むこと。どちらの画面のスキャナーでも、休止中でも読める。シミュレーターではレジ見出しのセレクタでも選べ、「未ログイン」を選ぶとログアウトになる。
- ログインすると、そのレジの呼び出し（FF・サービス・年齢確認・公共料金・現金・たばこ・電子マネー・お呼び出し）はすべて解除され、呼び出しボタンの鳴動も止まる。ただしサービス商品の受付が済んでいなければサービスの呼び出しは残る。仕事そのもの（FF のお渡し、年齢確認など）は取引に残る。スタッフ対応が要るものが取引に残っていれば、ログアウトするとその呼び出しは立ち直る（11.1）。
- たばこの呼び出し中にログインすると、たばこを登録するまで Item のたばこが点滅する。

### 4.2 操作側

レジの 2 つの画面は同じ取引を映す。どちらから操作できるかは `active_side` で決まる。

| 状態 | 操作側 |
| --- | --- |
| 店舗メニューを開いている | スタッフ側だけ |
| ログインしていない | お客様側だけ |
| セルフ操作モードで会計に進んだ後、ログインまで（`customer_turn`） | お客様側だけ |
| スタッフ操作モードで、どちらかの画面を操作した直後 1 秒（`TOUCH_LOCK_MS`） | 操作した側だけ |
| それ以外のスタッフ操作モード | 両方 |

- 機器の操作（スキャン・現金の投入・決済端末にかざす・ログアウト）は操作側に関係なく受け付ける。
- 次の操作はスタッフ側の画面からしか押せない：年齢確認の「する／スキップ」、生年月日の判定、公共料金の払込票の確認とお渡し、収入印紙の貼り付け確認、FF のお渡し照合。
- スタッフ側のベル（応援）は操作側に関係なく押せる。

| 操作 | スタッフ操作モード | セルフ操作モード |
| --- | --- | --- |
| スキャン | 可 | 可 |

| クーポンの取り消し | クーポンがあるとき（会計中も可） | 同左 |

### 4.4 画面の言語

- レジ画面は日本語と英語を切り替えられる。標準は日本語。
- 言語は画面ごと（レジ×スタッフ側／お客様側）に持つ。待ち受けの帯の「Language／言語」を押すと、押した側の画面だけが日本語と英語の間で切り替わる。もう一方の画面は変わらない。
- セルフ操作モードのスタッフ側の画面は操作できないので、言語も切り替えられない（ボタンは表示のみ）。
- 取引が終わると（お礼・お釣り・払込票や荷物のお渡しの画面が消えて待ち受けに戻ると、取引中止も含む）、そのレジの両方の画面が日本語に戻る。言語は保存しない。
- 画面は日本語で組み立て、英語の画面では表示する直前に訳す（`web/src/i18n.ts`）。訳すのはレジ画面（ヘッダー・本体・FF/呼び出しボタン・テンキー）だけで、シミュレーターの枠（Item・Wallet・Bell・入出金ボックス・決済端末・販売規則の設定）は日本語のまま。「Language／言語」ボタン自体は両言語併記で訳さない。

## 5. 取引

### 5.1 明細

- 明細には番号（取引内の通し番号）と最終更新順（`touched`）がある。画面は更新の新しい行ほど上に出す。クーポンも同じ通し番号を使う。
- 同じ商品を続けて読んだときだけ、直前の行の数量を増やす。間に別の商品を挟んだら新しい行になる。サービス商品はまとめない。
- 明細には登録した時点の税区分と税率を残す。あとで税率を変えても登録済みの明細は変わらない。
- 買い物点数（数量の合計）の上限は 100 点。超える登録はできず、ブラウザの警告で知らせる（たくさんの買い物で合計が税抜 5 万円を超え、レシートに収入印紙が要るケースを再現できるように 10 点から引き上げた）。
- オーナーが決めた販売個数の上限（1 回のお会計で n 点まで）を超える登録はできず、ブラウザの警告で知らせる。
- 数量の変更は登録画面で行う。「−」「＋」で 1 つずつ、数字を押すとテンキーで打ち込む（2 桁まで、0 は不可）。数量 1 の「−」は「削除」になる。サービス商品の数量は変えられない。
- 数量を変えても行の並びは変えない。

### 5.2 一緒に登録できないもの

| 対象 | 規則 |
| --- | --- |
| 公共料金の払込票 | ほかの商品と同じ取引に登録できない（どちらを先に読んでも） |
| 荷物を送る | 荷物を送る同士でなければ同じ取引にできない |
| 荷物を受取る | 一件ずつ、ほかの商品と別に扱う |

### 5.3 取り消しの制限

| 対象 | 規則 |
| --- | --- |
| 公共料金の払込票 | 明細ごとには取り消せない。やめるときは取引中止 |
| 荷物を送る | 取り消す荷物の伝票のバーコード（`PS…`）を、ログインしたスタッフがスタッフ側で読む。会計中は不可 |
| 荷物を受取る | 取り消せない。受け取らないなら取引中止 |
| お渡し済みの FF | スタッフがログインしているときだけ。取り消した分は回収の案内が出る |

### 5.4 クーポン

- 引換券は対象商品 1 個の価格、割引券は対象商品 1 個から指定額（価格を上限）を値引きする。
- 対象商品 1 個につきクーポン 1 枚が効く。商品より先に読んでもよい。対象商品がなければ「対象商品待ち」。
- 値引きは対象商品の税率の対象額から引く。
- 会計に進んで適用先のないクーポンが残っていると決済できない。対象商品を登録するか、クーポンを取り消す。
- 取り消したクーポンはお客様に返す。「返却しました」（スタッフ側）・「受け取りました」（セルフ操作モード）で案内を閉じる。

### 5.5 ポイントカード

- いつ読んでもよい。読むとヘッダーの帯に「ポイント：読取済」と出る。
- 会計ボタンの後、ポイントの付与対象がある取引で未読取なら「ポイントを付与しますか？」の確認を出す。「付与する」は読み取りの案内を出し、そのまま読めば確認済みになる。右下の「スキップ」でカードなしで進む。
- 公共料金の取引と、付与対象の商品がない取引では確認しない。
- 付与対象外：荷物を送る・荷物を受取る・公共料金・切手・たばこ。
- 付与ポイントは、付与対象の商品の合計（取引の合計が上限）を 100 で割った数。

### 5.6 フラグ

- フラグは取引の阻害因子（決済に進めない理由）にだけ付く。確認や入力を終えるとフラグは外れる。済んだことを示す札（お渡し済・年確済・受付済など）や、限定n・現金のみの札は出さない。
- フラグのある明細は行ごと淡いオレンジ（`oklch(0.68 0.14 50)` 45% を白に混ぜた色。ピンクの背景の上でも沈まない濃さ）に染まる。フラグは別画面を呼び出す部品なので、商品名の右隣の小さな消極ボタン（操作できる側では青枠・青文字・背景なし、弱い角丸）。操作できない側では同じ形のグレー。明細の「削除」「−」「＋」は行の色に関わらず入金ボックスと同じグレーの消極ボタン。
- フラグ：「年確20」（年齢確認前）、「お渡し前」（FF の照合前）、「受付待ち」（サービス商品）、「受付中」「届け先未定」（荷物を送る）、「照合待ち」「見つかりません」（荷物を受取る）。
- 押して解消できるフラグはボタンになる（スタッフ側の「年確20」「お渡し前」）。いつ解消するかはスタッフが決める。
- フラグを全部解消しないと決済選択に進めない。順序は フラグ → ポイントカード → 決済選択。電子マネーのチャージ・残高照会は別枠で、決済完了前・取引中止前ならいつでも割り込める。
- 「お渡し前」が残ったまま会計ボタンを押すと、お渡し照合の画面を開く。「年確20」が残ったまま会計ボタンを押すと、年齢確認から始める。

## 6. 会計

### 6.1 会計ボタン

会計ボタン（セルフ操作モードは「お会計」）を押すと次を行う。

1. まだ確認していない年確年齢のうち最も高いものを、求める年齢にする（なければ明細の最も高い年齢）。まだ確認していない年齢があれば年齢確認をやり直す。
2. ポイントカードの確認が要るか決める（5.5）。
3. セルフ操作モードなら、支払いをお客様側に任せる（`customer_turn`）。
4. 公共料金があれば支払方法を現金に決める。払込票の確認が済んでいなければ、セルフ操作モードでは公共料金の呼び出しをかける。
5. セルフ操作モードで現金のみの商品（切手）があれば現金の呼び出しをかける。
6. セルフ操作モードで年齢確認が要れば年齢確認の呼び出しをかける。

会計画面でバーコードを読む、または FF を登録すると、登録画面に戻って追加する（投入済みの現金はそのまま）。例外として、ポイントカードの確認中に読んだポイントカードは確認済みになり、会計画面にとどまる。点数や販売個数の上限で登録できないときも会計画面にとどまる。

### 6.2 確認の順序

一つの画面では一つの確認だけを出す。確認は登録画面を置き換えて出す。順序は次のとおり。

| 順 | 確認 | 出す側 |
| --- | --- | --- |
| 1 | 取引中止の確認 | 押した側（スタッフ操作モードのお客様側には対になる案内） |
| 2 | 荷物を受取るの照合（登録中） | スタッフ側 |
| 3 | 荷物を送るのサイズ・郵便番号（登録中） | スタッフ側 |
| 4 | 次の荷物はありますか（登録中） | スタッフ側 |
| 5 | 公共料金の払込票の確認 → 収入印紙の貼り付け確認 → 支払いの案内 | スタッフ側 |
| 6 | 年齢確認 | スタッフ側 |
| 7 | 販売できない商品の回収・FF の回収・適用先のないクーポン・クーポンの返却 | スタッフ側 |
| 8 | ポイントカードの確認 | スタッフ操作モードはスタッフ側、セルフ操作モードはお客様側 |
| 9 | 決済手段 | 同上 |

確認の最中、操作しない側には対になる案内を出す（例：「スタッフが払込票を確認しています」）。

### 6.3 決済の関門

次のどれかがあると、現金の投入も決済端末も受け付けない。理由は上から順に一つだけ返す（`payment_blocker`）。

1. 電子マネーの残高不足に答えていない
2. 販売期限切れの商品がある（会計そのものも押せない）
3. スタッフが払込票の内容を確認していない
4. 収入印紙の貼り付けが確認できていない（5 万円以上の払込票は領収証に印紙 200 円。税金の払込票は非課税なので要らない。通常のお買い物は、税抜 5 万円以上をクレジットカード以外で受け取ると、決済のあとにレシートの収入印紙の貼り付け確認がスタッフ側に出る（お釣り・お礼の案内の前。セルフ操作モードでスタッフがいなければ「収入印紙」で呼び出す）。明細のフラグ「印紙貼付前」から登録中でも確認でき、会計では払込票の確認のあとにスタッフ側へ出る。一枚ずつチェック）
5. セルフ操作モードで現金のみの商品がある
6. セルフ操作モードで支払方法に現金が選ばれた
7. 年齢確認のやり方を選んでいない
8. 生年月日を入力していない
9. ポイントカードの確認が済んでいない
10. 適用先のないクーポンがある
11. FF のお渡し照合が済んでいない
12. サービス商品の受付が済んでいない
13. 次の荷物の有無に答えていない

### 6.4 支払方法

支払方法は現金・電子マネー・バーコード決済・クレジットカード・ポイント利用の 5 つ。

- 現金と併用できるのは電子マネーだけ。現金のみの商品（切手・公共料金）がある取引では、バーコード決済とクレジットカードは選べない。
- 現金のみの商品だけの取引では、キャッシュレスは選べない。
- ポイント利用は付与対象の商品の分だけに使え、1 回の会計で一度だけ（キャッシュレスで先に払った分があると使えない）。付与対象がなければ選べない。ポイントカードを読まずに選ぶと、ポイントカードの確認に戻る。
- 選択中の支払方法をもう一度押すと選択を外す（待ち受けの案内ボタンと同じ挙動）。ただし現金が投入済みのときと、セルフ操作モードの「現金」（店員呼び出し）は外さない。
- 現金を投入した後は、現金以外を選べない。
- 電子マネー・クレジットカードは決済端末に、決済用バーコード・ポイントカードはスキャナにかざす。選んだ支払方法と違うものは受け付けない。
- 使えない支払方法のボタンは押せず、理由を出す（コアの `unavailable`）。

セルフ操作モードはキャッシュレス専用。支払方法の一覧に現金はなく、右下の消極ボタン「現金」を押すと現金の呼び出しがかかり、スタッフがログインして預かる。お客様側画面は支払方法の選択から二行の案内画面「現金は店員がお預かりいたします」「店員が向かっています」に切り替わる。案内画面の「バック」で引き返すと、その呼び出しは片付く（現金のみの商品があるときは残す）。

スタッフ操作モードでは支払方法はスタッフ側で選ぶ。お客様側には一覧を押せない形で見せる。

### 6.5 現金

- 現金はスタッフが預かり、スタッフ側の入金ボックスに入れる。お客様側に落としても入らない。
- 入金ボックスを押すとテンキーが開き、金額を打って「決定」で入れる。何も打たずに「決定」すると、入れた分で投入を終える。Wallet のお金をドラッグしても入る（金種は大きい順に崩したものとみなす）。ただし Wallet の二千円札は取り扱わない札として扱い、入金ボックスに入れてもそのまま出金ボックスに吐き出す（テンキーで 2000 と打つのは千円札 2 枚とみなす）。出金ボックスに二千円札があるあいだ、両画面を案内画面に置き換える（スタッフ側「二千円札を返却しました／取り扱い対象外の紙幣です／出金ボックスからお客様にお返しください」、お客様側「二千円札はご利用いただけません／スタッフがお返しいたします」）。取り出すと消える。
- 投入額は積み上がる。スタッフ側の会計ボタンの位置が「投入おわり」になり、足りていれば押して決済する。
- 足りた状態で最後の投入から 30 秒（`INSERT_DONE_MS`）入れなければ、投入おわりとみなして決済する。
- 案内：スタッフ側は不足時「あと〇円不足しています」、足りていれば「〇秒の無操作で、お支払いを確定します」。お客様側は不足時「不足額〇円」、足りていれば「追加投入の受付 残り〇秒」。
- お釣りは一万円札・二千円札を使わずに大きい金種から出す。釣銭機に足りなければ決済せず「釣銭機の在高が不足しています」。
- お釣りは出金ボックスに出る。出金ボックスを押すと取り出す。

### 6.6 キャッシュレスで先に払う分

- 現金のみの商品がある取引で電子マネーを選ぶと、まず現金のみの商品を除いた分を電子マネーで払い、残りを現金で払う。
- ポイント利用で付与対象の分を払ったあと、残りが現金のみの商品だけなら現金、ほかが残れば支払方法を選び直す。
- 先に払った分があると登録画面には戻れない。
- 取引中止では、電子マネーで先に払った分は残高に戻し、ほかのキャッシュレスは取り消す。

### 6.7 電子マネーの残高不足

電子マネーでかざして残高が足りないと、決済を止めて選んでもらう。画面には不足額だけを出す。

| 選択 | スタッフ操作モード | セルフ操作モード |
| --- | --- | --- |
| 他の決済を使う | 可（左下。支払方法を選び直す） | 可（右の積極ボタン。スタッフを呼ぶ前だけ） |
| 不足額を現金で払う | 可 | 「チャージまたは現金併用」でスタッフを呼ぶ |
| 電子マネーをチャージする | 可 | 同上 |

- セルフ操作モードでは、残高が足りなくなった時点ではスタッフを呼ばない（お客様が他の決済を選ぶとスタッフが無駄足になる）。左の消極ボタン「チャージまたは現金併用」を押すと電子マネーの呼び出し（詳細「残高不足」）をかけ、お客様側は「スタッフが向かっています」だけになる。呼んだあとは「他の決済を使う」を出さず、受け付けもしない。スタッフがログインすると、スタッフ操作モードのこの画面につながる。

- 「不足額を現金で払う」は、まず「電子マネーの残高〇円を引き出し、残り〇円を現金でお支払いいただきます」を出す。「確認しました」を押してから電子マネーをかざすと残高を引き出し、残りを現金で払う。確認前にかざしても引き落とさない。引き出したあとは、両画面の合計が残りのお支払い額（例：2,200円の買い物を残高1,000円で払うと1,200円）に変わる。ポイント利用・現金のみの商品で一部を先に払ったときも同じ。
- 「チャージする」はチャージの手続き（7 章）を開く。チャージが済んだら、もう一度かざす。

### 6.8 決済

決済すると次を行う。

- レシート番号を振り、合計・支払方法・支払額・お釣り・点数・ポイントカード・付与ポイントを残す。先に払った分がある場合の支払方法は「電子マネー・現金」「ポイント利用・クレジットカード」のように組み合わせて表す。
- 取引を空にし、そのレジの呼び出し（釣銭忘れ以外）を片付ける。
- 公共料金なら払込票のお渡し待ち、荷物を受取るなら荷物の引き渡し待ちにする。
- 画面は「ありがとうございました／お忘れ物にご注意ください」を 3 秒（`THANKS_MS`）出して待ち受けに戻る。出金ボックスにお金がある間、払込票・荷物のお渡し待ちの間は戻らない。スタッフ操作モードでお釣りがある間は、スタッフ側に「お釣り〇円をお返ししてください」、お客様側に「お釣り〇円とレシートをお受け取りください」を出し、取り出した時点から 3 秒の「ありがとうございました」になる。
- 次のスキャンで、払込票・荷物のお渡しは済んだものとする。

### 6.9 釣銭忘れ

出金ボックスにお金が残ったままだと、

- セルフ操作モードは 1 分、スタッフ操作モードは 30 秒で、お客様側に「釣り銭が残っています」を出す。
- セルフ操作モードは 2 分、スタッフ操作モードは 1 分で、釣銭忘れの呼び出しをかける。
- 取り出すと呼び出しは片付き、止めていた無操作のカウントダウンを続きから再開する。

## 7. 電子マネーのチャージ・残高確認

- 入口は未定（2026-11-06 にヘッダーから取り除いた。置き場所は検討中）。
- セルフ操作モードのお買い物の途中（明細・クーポン・返却待ちのクーポンがある）は、ボタンは押している間スタッフを呼ぶ呼び出しボタンになる。
- 押すと「チャージ」「残高確認」を選ぶ画面になる。
- 残高確認：決済端末にかざすと残高を出す。
- チャージ：入金ボックスに紙幣（千円札以上）を入れてから、決済端末にかざす。残高の上限は 20,000 円。セルフ操作モードでチャージを選ぶと、手続きは開かずに電子マネーの呼び出しをかける。
- 「バック」で閉じる。チャージ用に入れた紙幣は出金ボックスに戻す。
- 財布の電子マネーの最初の残高は 1,000 円。

## 8. FF

- スタッフ操作モードのスタッフ側で、画面下のタブから登録する。
- ボタンに在庫数は出さない。在庫は 3 段階で見せる：潤沢（3 個以上）＝積極ボタン、品薄（1〜2 個）＝消極ボタン、欠品（理論上 0）＝グレーアウト。品薄の境目はコアの `FF_LOW_STOCK`（2）。
- FF の単品ボタンは別画面に移らない部品なので、角に丸みのない四角にする（積極・消極・グレーアウトの三段階はそのまま）。タブとも形で役割を分ける。
- 欠品のボタンは押しても登録しない。長押し（0.5 秒）で予約注文として登録する（作り置きがないときの受け付け用）。在庫は 0 のまま。
- 在庫が足りないときの案内は「〇〇は欠品です（FF ボタンの長押しで予約注文として登録できます）」。残数は出さない。明細の「＋」・個数入力で在庫を超えて増やすことはできない。
- セルフ操作モードでは画面下に呼び出しボタン「FF（揚げ物・中華まん）」「サービス（お支払い・荷物）」「金券（ギフトカード・印紙）」「たばこ（紙巻き・電子）」が並ぶ。押している間 Bell が鳴る。
- 登録した FF は「お渡し前」のフラグが付く（5.6）。スタッフ側の明細の「お渡し前」フラグ、または会計ボタンでお渡し照合の画面を開く。照合が済むとフラグは外れる。
- 照合の画面は「お渡しした数を入力してください」と 品目｜注文数｜お渡し数｜照合 の表。お渡し数を打つと、その場で注文数と比べて OK・NG を出す。注文数 1 の行はチェックボックスで照合する。すべて OK になると照合イベントの済んだ案内（9.1）を出し、「次へ」で登録画面に戻る。お客様側には出さない。「バック」で途中でも戻れる。
- 照合が済むまで会計に進めない。照合はスタッフの責任で、スタッフ側の画面でだけ行う。ログアウト後はお客様側では照合できない。お客様側には「お渡し前」を出さない。
- お渡し済みの FF を増やすと、増やした分だけがお渡し前に戻り、追加分だけを照合する。
- お渡し済みの FF を減らす・取り消すと、回収イベントの共通の形（9.1）で「お渡し済みのFFが取り消されました」「お客様からFFを回収してください」と品名・減らした点数を出し、「回収しました」で閉じる。お客様側には回収の案内を出さず、「〇〇の数量を変更しました」を縦横中央に出す（お渡しも回収もスタッフが取り仕切る。お客様への回収の案内は混乱の元）。
- お渡し前の FF を減らす・取り消すと在庫に戻す。

## 9. 年齢確認

- 年確の対象は年確ルール（12.1）で決まる。会計ボタンを押したときに、対象が複数あれば最も高い年齢で 1 回行う。
- 年齢確認前の年確商品の明細には「年確20」のフラグが付く（5.6、お客様側にも出す）。
- スタッフ操作モードでは、登録の途中でもスタッフ側の「年確20」フラグを押して年齢確認を始められる。販売できない客に早めに伝え、ほかの商品まで登録してから取引ごと取りやめになるのを防ぐため。年齢確認の画面が登録画面を置き換え、左下の「バック」で登録画面に戻る。済んだら登録画面に戻る。
- 年齢確認が済むとフラグと行の警告色が外れ、会計で再び尋ねない。年齢に届かなければ年確商品を明細から取り除く（「スキップ」を選んだときは取り除かない）。確認は年齢ごとに済む。年齢確認の後に、まだ確認していない年齢の年確商品が加わったら（20歳の確認の後の花火＝18歳など）、その明細に「年確18」が付き、会計でその年齢の確認をやり直す。すでに確認した年齢の年確商品（ライターの後のたばこカートンなど）や、同じ明細の数量を増やしただけではやり直さない。
- スタッフ側に「〇歳以上の年齢確認をしますか？」を出す（お客様側は「年齢確認が必要な商品が含まれています」）。「する」で生年月日の入力、右下の「スキップ」でスタッフの判断で済ませる。
- 認める身分証は年齢制限の種類で変わる。まだ確認していない年確商品に法令の年齢制限（酒・たばこ）があれば運転免許証またはマイナンバーカード。店舗が任意で決めた年齢制限（花火など）だけなら学生証など顔写真付きの身分証も認める。デジタル身分証は偽造が容易なので、どちらでも認めない（コアの `age_official_id`）。外国人の在留カード・特別永住者証明書・パスポートは法令の年確でも認める。並べて書くと日本人にも外国人にも冗長なので、お客様側では法令の年確のときだけ、日本語の案内の下に英語で一行添える（店舗が任意で決めた年確には添えない。日本語を介さない外国人の小中高生が花火やライターを買うのはまれ。「Also OK: Residence Card, Special Permanent Resident Certificate, Passport」、言語切り替えでも訳さない）。スタッフ側は「在留カード・特別永住者証明書・パスポートも可」。生年月日の入力画面の小さなテキストでスタッフに示す（「運転免許証またはマイナンバーカードで確認してください」／「学生証など顔写真付きの身分証で確認できます」「デジタル身分証は不可」）。
- 「する」を選ぶと、お客様側は「年齢確認が必要な商品が含まれています」と、法令なら「免許証またはマイナンバーカードの提示をお願いいたします」、店舗の任意だけなら「学生証など顔写真付きの身分証の提示をお願いいたします」「デジタル身分証はご利用いただけません」。スタッフが生年月日の入力を始める（テンキーを開く）と、お客様側は「生年月日から年齢を判定しています」「端末は個人情報を保存しません」に切り替わる。
- 生年月日は身分証の西暦 8 桁（例 19821002）をテンキーで打ち、テンキーの「決定」でそのまま判定する（画面に「判定」ボタンは置かない）。8 桁でない・存在しない日付（1900 年より前を含む）・今日より後は判定せず、テンキーを開いたまま理由を出す。年齢は誕生日の当日に加算する。
- 入力欄がひとつだけの画面（生年月日・荷物の長さ・重さ・郵便番号・使うポイント数）は、どれもテンキーの「決定」で送る。テンキーの「決定」と画面の決定ボタンがほぼ同じ位置に重なり、二度押しが要るように見えたため（動作試験 第2回）。
- 年齢が足りていれば照合イベントの済んだ案内（9.1）を出す。スタッフ側「〇歳以上であることを確認しました」「身分証をお返しください」と「次へ」、お客様側「年齢確認が完了しました」「ご協力ありがとうございました」。年確商品の販売は責任が重いので、手ごたえなしにポイントの確認などへ進めない。スキップは確かめていないので出さない。
- 年齢に届かない年確商品は取引から取り除き、回収イベントの共通の形（9.1）で出す。スタッフ側「年齢制限により販売できない商品があります」「お客様にお詫びし、商品を回収してください」・品名と点数・「回収しました」、お客様側「年齢制限によりお売りできない商品があります」「申し訳ございません、こちらの商品はお会計から外させていただきます」と品名・点数。すべて取り除いたら登録画面に戻る。
- セルフ操作モードでは年齢確認の呼び出しをかけ、お客様側に「年齢確認が必要な商品が含まれています／〇歳前後のお客様は身分証をご準備ください」を出す。スタッフがログインしてから確認する。

### 9.1 照合イベントと回収イベント

呼び出しイベント（どの種類も画面構成と挙動が同じ）と同じく、照合と回収もそれぞれ一つの形に揃える。

- 照合イベント（年確の判定・FF のお渡し照合）：スタッフが数字（生年月日・お渡し数）を打ち、システムがその場で判定する。済んだら登録画面に戻す前に、縦横中央に緑の丸の ✓・大きなテキスト（何を確かめたか）・小さなテキスト・「次へ」を出し、「ピンポン」と鳴らす。スタッフにシステムのお墨付きを返すため。お客様側に出すときは完了とお礼（「次へ」はスタッフ側だけ）。コアの `passed`、閉じるのは `dismiss_passed`。
- 回収イベント（年確で販売できない商品・お渡し済み FF の取り消し・販売期限切れ）：縦横中央に、大きなテキスト＝なぜ回収するか、小さなテキスト＝スタッフへの指示（お客様側はお詫び）、回収する品名と点数（販売期限切れは販売期限）の一覧、スタッフ側だけ「回収しました」。チェックボックスは置かない。バックは品が明細に残る販売期限切れだけ（ほかは品がもう明細にないので、バックしても同じ案内が残るだけ）。FF の回収はお客様側に回収の案内を出さず「〇〇の数量を変更しました」だけ。

## 10. サービス商品

### 10.1 荷物を送る

- 伝票（発払い・着払い）を読むと受付中の明細ができ、伝票番号（12 桁）を振る。スタッフがいなければサービスの呼び出しをかけ、お客様側に「スタッフがお伺いします／伝票を貼り付けてお待ちください／伝票の貼り付け、梱包はお客様責となります」を出す。

### 10.2 荷物を受取る

- お客様の受取用バーコードを読むと、お預かりの荷物の番号（12 桁）と代金引換の金額（1,000〜9,900 円、100 円単位）が決まり、金額はすぐ合計に入る。スタッフがいなければサービスの呼び出しをかける。
- 照合と引き渡しはログインしたスタッフがスタッフ側で行う。スタッフ側には番号を大きく出し、「保管場所に荷物はありましたか？」に「有り」「無し」で答える。保管場所の荷物のバーコード（`PK…`）を読んでも照合できる。番号が違えば「番号が違います／この荷物はお渡しできません」。
- 有り：照合済みになり、会計できる。一度有りにしたら探し直さない。
- 無し：「お客様にお詫びし、運送会社へお問い合わせください」。「探し直す」で戻るか、「お受け取りを終える」で支払いなしに取引を終える。
- 代金引換の決済の後、スタッフ側に「店舗控えにサインをいただき、荷物をお渡しください」と「お渡ししました」、お客様側に「受け取りのサインをお願いします」を出す。
- お客様側には照合中「荷物をお持ちします」、見つからなければ「申し訳ございません」を出す。

### 10.3 公共料金

- 払込票は普通の商品と同じく読む。一枚ずつ明細にし、同じ事業者でもまとめない。払込票番号（16 桁、4 桁区切り）を振る。
- 現金のみ、ポイントは付かない。
- 会計ボタンの後、スタッフが一枚ずつ内容を確かめてチェックを入れる。表は 事業者｜金額｜バーコード番号｜確認 で、見出しに受付枚数と合計。チェックは外せる。数字の打ち込みはさせない。
- セルフ操作モードでは会計ボタンで公共料金の呼び出しをかけ、お客様側に「払込票の内容を確認いたします」を出す。呼び出し中のスタッフ側には枚数を大きく出す。
- 確認が済むと、お客様側に「公共料金n枚を受け付けます／現金でお支払いください」（セルフ操作モードでは「現金はスタッフがお預かりします／スタッフをお呼びください」）、スタッフ側に「お客様に受付点数、合計金額をお伝えください」を出す。
- 決済の後、スタッフ側に「払込票に収納印を押してお渡しください」と「お渡し済」、お客様側に「払込票とレシート、お釣りをお受け取りください」を出す。受付枚数はどの画面でも大きく出す。

## 11. 店員呼び出しと Bell

### 11.1 呼び出し

呼び出しはレジ・種類ごとに一件の独立した記録で、同じレジの同じ種類は重ねて立てない。順番待ちはしない。

| FF の注文 | FF | FF ボタン | FF の登録・ログイン・決済・取引中止 |
| サービス受付 | サービス | サービスボタン、スタッフ不在でのサービス商品の読み取り | 受付が済む・ログイン（受付待ちがなければ）・決済・取引中止 |
| 金券 | 金券 | 金券ボタン | ログイン・決済・取引中止 |
| たばこ | 煙草 | たばこボタン | ログイン・決済・取引中止 |
| お呼び出し | 呼び出し | お客様側のベル | ログイン |
| 釣銭忘れ | 釣銭忘れ | 出金ボックスの放置（6.9） | 取り出す |
| 公共料金 | 公共料金 | セルフ操作モードで公共料金の会計 | 全払込票の確認・ログイン・決済・取引中止 |
| 電子マネー | 電子マネー | セルフ操作モードのお買い物の途中のチャージ・残高確認ボタン、チャージの選択 | ログイン・決済・取引中止 |
| 現金 | 現金 | セルフ操作モードで切手の会計、現金の選択 | ログイン・ほかの支払方法の選択・決済・取引中止 |
| 収入印紙 | 収入印紙 | セルフ操作モードで、税抜 5 万円以上の決済のあとの印紙の貼り付け確認 | 貼り付けの確認 |

- スタッフ対応が要る呼び出しは、出来事で立てるのではなく取引の状態から導く。セルフ操作モードでは、コマンドと `tick` のたびに今の状態で必要な呼び出し（コアの `Register::required_calls`）を計算し、立っていないものを立てる。だから、ログインで呼び出しが片付いたあと対応せずにログアウトしても、取引に残っていれば立ち直る。片付けるのは今までどおり、対応が済んだときの各操作。

| 種類 | 状態から立つ条件 |
| --- | --- |
| 販売期限切れ | 期限切れの明細がある |
| サービス受付 | 受付待ちのサービス商品がある |
| 公共料金 | 会計中で、払込票がある |
| 年齢確認 | 会計中で、年齢確認が済んでいない |
| 現金 | 会計中で、現金のみの商品がある、または支払方法に現金を選んでいる（払込票の取引を除く） |
| 収入印紙 | 決済のあと、レシートの収入印紙の貼り付け確認を待っている |

- ボタンで立てる呼び出し（ベル・FF・サービス・金券・たばこ・電子マネー）は出来事のまま。
- スタッフがログインしているレジでは、ボタンでの呼び出しは記録しない（Bell は鳴る）。
- 解決した呼び出しは直近 30 件を履歴に残す。
- 呼び出し中は、そのレジの両方の画面のヘッダー中央（ベルのまわり）がやわらかい黄色で点滅する。点滅の速さも色も待ち時間で変えない（経過時間がお客様にも伝わり、待たされた不満を増やしかねないため）。
- 応答のない呼び出しがあるあいだ、Bell は最後に鳴ってから 30 秒ごとに、3 回まで鳴らし直す（`BELL_REMIND_MS`・`BELL_REMINDS`）。お客様が押す・新しい呼び出しが立つと数え直す。鳴り続けるとレジ台数が増えたときの騒音になり、繰り返される音に人は鈍くなって、かえって呼び出しに気づきにくくなるため。鳴らし直しは非常事態モード（11.4）の判定に関わらない。
- セルフ操作モードで応答のない呼び出しがあるあいだは、種類を問わず（ベル・FF・サービス・宅配便・金券・たばこ・電子マネー・年齢確認・公共料金・現金・収入印紙・販売期限切れ・釣銭忘れ）、最下段の呼び出しボタンを、お客様側は「スタッフを呼び出しています」（添え字なし）、スタッフ側は呼び出しからの経過秒数（例「12秒経過」）に置き換える。取り消しボタンは置かない。最下段の背景は、ヘッダーの呼び出しの点滅と同じ拍で薄い黄（`--alert-bg`）と濃い黄（`--call-soft`）を行き来する。三段目の明細は残すので、待つあいだも商品を登録できる（受付待ちのサービス商品が呼んでいるサービスの呼び出しは、この案内の対象にしない）。
- スタッフがログインすると、応答した用件（呼び鈴と釣銭忘れ以外のすべての呼び出し）の最初の一件を取引が終わるまでスタッフ側の担当スタッフ名の右に「用件：たばこ」と出す。
- セルフ操作モードの呼び出し中、スタッフ側の画面は最初の呼び出しの用件一件（「＆」で繋がない。残りはスタッフがレジに着けばお客様との対話でわかる）だけを第一待ち受けの「セルフレジ」と同じ特大の文字で出し（長い用件は幅に合わせて小さくする）、小さなテキストで「鳴動を止めるにはログインしてください」を添える。呼び鈴の絵・詳細・経過時間は出さない（経過秒数は最下段）。公共料金の枚数だけは残す。用件は具体的に：最下段のボタン（FF・サービス・金券・たばこ）はボタンの文言、公共料金の払込票は「お支払い」、荷物の伝票は「宅配便」、年確・電子マネー・収入印紙・販売期限切れはその名前、現金のみの商品は商品名（チケット・切手）、お支払い方法の現金は「現金」。
- スタッフ操作モードのお客様側には、呼び出しがあれば「スタッフが向かっています」を出す（年齢確認の画面を出している間の年齢確認の呼び出しは除く）。

### 11.2 ベル

- お客様側のベル（ヘッダー中央）はスタッフを呼ぶ。押している間 Bell が鳴る。スタッフ操作モードでは出さない。
- スタッフ側のベルは仲間のスタッフに応援を頼む。ログインの有無を問わず押せ、Bell を鳴らすだけで呼び出しの記録・画面表示はない。
- 呼び出しボタン（ベル・FF・サービス・たばこ・お買い物の途中の電子マネー）は押している間だけ鳴る。指を離す、指がボタンから外れる、ウィンドウを離れると止まる。キーボードでは Space・Enter を押している間。スタッフがログインすると止まる。

| 4 台目以降 | 可搬性端末n | 携帯 | ON/OFF できる |

- Bell は鳴るだけで、呼び出しの内容は出さない。
- レジ側は鳴動状態（版数・押されているレジの数・押した回数）を送り、Bell は受け取った版数を返す。返事が最新に追いつくまで 200ms ごとに再送し、変化がなくても 2 秒ごとに送る。5 秒返事がなければ不通。
- 押されている間は鳴り続ける。押した回数が増えたことを受け取ると最短 1 秒鳴る。受信が途絶えたら鳴り止む。
- 不通の Bell があると、スタッフ側に「〇〇 不通：呼び出しが届きません」を出す。呼び鈴機能が OFF の端末は鳴らず、不通も出さない。ON に戻したとき、OFF の間の呼び出しでは鳴らさない。
- 呼び出しの音量は、最も長く待たせている呼び出しの放置時間で 0.25 から 1 まで 60 秒かけて大きくなる。音は消せない。
- シミュレーターは通信ロス率と端末の不通を設定できる（`set_bell_loss`・`set_bell_offline`）。

### 11.4 非常事態モード

セルフ操作モードでスタッフに連絡が付かない状況を、事件・事故の可能性とみなしてお客様に通報をお願いする。

- 発動：セルフ操作モードでそのレジにスタッフがログインしていないまま、未解決の呼び出しのうち最も古いものが立ってから 5 分（`EMERGENCY_UNANSWERED_MS`）たったとき。押した回数ではなく、待たせた時間で決める。何度押しても 5 分未満なら発動しない。
- 対象の呼び出しは種類を問わない。ただし釣銭忘れは数えない（お客様はもう立ち去っている）。
- 数え始めは最も古い未解決の呼び出しが立った時刻。お客様がもう一度押しても数え直さない。
- 応答はスタッフのログイン。ログインで呼び出しが片付けば待ち時間も消え、ログアウトしたあとは新しい呼び出しから数え直す。
- 呼び鈴が不通でも発動する（スタッフが応答しない状況には違いない）。
- スーパーバイザーやオーナーへの通知は送らない。24 時間 365 日の店舗で、社員やオーナーが即座に対処することはできない。店内で 5 分応答がないことは通常ありえず、その時点で異常とみなす。
- 画面：両画面のヘッダーの稼働モードが「非常事態モード」になり、ヘッダーと最下段が赤（`--sos-head`）と黄で点滅する。お客様側は「スタッフの応答がありません」「事件または事故の可能性があります／ご自身の安全を確保の上、通報をお願いいたします」と「警察：110　消防救急：119」「緊急連絡先と店舗住所を記載したレシートを出力します」、最下段に英語で「Stay alert／Please call emergency services」（言語切り替えでも訳さない）。スタッフ側は「非常事態モードを解除します」と「解除」、最下段にオーナーと担当スーパーバイザーの連絡先。
- 解除：スタッフ側の「解除」はログインなしで誰でも押せる（駆け付けた警察官・救急隊が解除する）。ログインしただけでは解除しない。解除すると呼び鈴（お呼び出し）の呼び出しを片付け、通常運転に戻る。ほかの用件の呼び出しは残し、解除した時刻から数え直す。
- 解除のレシート：解除と同時に発動時刻と解除時刻を印字したレシートを出し、スタッフ側に「非常事態モードを解除しました」「発動時刻と解除時刻を記載したレシートを出力しました」と両時刻を、10 秒（`EMERGENCY_LOG_MS`）か、そのレジの次の操作まで出す。

## 12. 取引中止・無操作・休止

### 12.1 取引中止

- 登録画面の上の帯の左端に「取引中止」を置く。明細かクーポンがあるとき押せる。セルフ操作モードのお客様も押せる。
- 押すと確認画面「取引を中止しますか？」を出し、点数・合計、戻るお金を示す。「はい」で中止、左下の「バック」で戻る。
- 中止すると、入れた現金とチャージ用の紙幣は出金ボックスへ、電子マネーで先に払った分は残高へ戻す。お渡し前の FF は在庫に戻す。取引に関わる呼び出しを片付け、店舗メニューを閉じる。

### 12.2 無操作

- 最後の操作から 5 分（`IDLE_REVERT_MS`）たつと、取引があれば中止し、ログインしていればログアウトしてセルフ操作モードに戻る。店舗メニュー・払込票と荷物のお渡し待ちも閉じる。
- 出金ボックスにお金がある間と、そのレジに呼び出しがある間は数えない。
- レジの見出しに残り時間を出す（例「無操作であと 4:12 で取引を中止してセルフ操作モードに戻ります」）。

### 12.3 休止・ログアウト

- 店舗メニューの「レジ休止中」でログアウトし、休止にする。休止中はスタッフバーコードと出金ボックスの取り出しだけを受け付け、両画面に「レジ休止中」（お客様側は「お手数ですが、ほかのレジをご利用ください」、スタッフ側は「スタッフバーコードを読むと再開します」）を出す。取引中は休止できない。
- 店舗メニューの「ログアウト」でセルフ操作モードに戻る。

## 13. 店舗メニュー

- スタッフ操作モードのスタッフ側で、ヘッダーを右へ 40px 以上スワイプすると開き、左へスワイプすると閉じる。マウスのドラッグでも同じ。休止中は開けない。
- 開いている間、操作はスタッフ側だけ。ヘッダーの稼働モードは「店舗処理モード」になり、お客様側には「休止中／空いているレジをお使い下さい」を出す。
- 項目：返品返金・緊急出金・取引外入金・経費支出・自動釣銭機（両替）・ジャーナル確認・廃棄登録・FF鮮度管理、ログアウト・レジ休止中。お金の出し入れを伴う項目は取引中は開けない。ジャーナル確認・廃棄登録・FF鮮度管理は「準備中です」。
- 各項目の画面は左下の「バック」で一覧に戻る。
- 返品返金・緊急出金・経費支出（お金を抜く操作）：金額と店舗パスワードをテンキーで入れて「出金」。パスワードは操作のたびに要り、●で表示し、送ったら成否にかかわらず消す。お金は出金ボックスに出る。
- 取引外入金：入金ボックスに金額を入れて決定。パスワードは不要。
- 両替：受け取る金種（1,000・500・100・50・10 円）を選び、入金ボックスに入れた額を同じ額の指定金種で出金ボックスに出す。金種の倍数でなければ受け付けない。
- お金の出し入れはすべて担当者名つきで記録する（監査ログ）。コアは途中集金・釣銭機回収・釣銭補充の種類も持つが、画面からは使わない。
- 釣銭機の初期在高：10,000×5、5,000×10、1,000×30、500×20、100×50、50×30、10×50、5×30、1×50。

## 14. 販売規則の設定

Item 見出しの歯車から開く。開くときにオーナーの番号とパスワードで認証し、閉じると認証を解除する。コアは変更のたびにも認証する。変更はすべて変更履歴に残る。設定はタブ（税率・年齢制限・個数制限）で切り替え、開いたときは左端の「税率」タブ。

### 14.1 年齢制限

- 法令ルール：酒類・たばこは 20 歳以上。外せず、変えられない。
- 店舗ルールの初期値：ライター 20 歳以上（18 禁書籍・アダルトグッズの分類の商品があれば 18 歳以上）。
- 商品ごとに なし・15・18・20 歳以上 から選ぶ。コアは分類単位のルールの追加・削除も持つ（1〜99 歳）。
- 表には 商品｜法令｜店舗の年確｜会計時の年確 を出す。

### 14.2 個数制限

- 商品ごとに 1 回のお会計の販売個数の上限を 制限なし・1〜5 点 から選ぶ（コアは 1〜99）。

### 14.3 税率

- 税区分：標準税率 10%・軽減税率 8%・ゼロ税率 0%・非課税・不課税 0%。ゼロ税率と非課税・不課税は 0% から変えられない。
- 区分の税率を変えられ（0.01% 単位、0〜100%）、区分を追加できる。商品ごとに区分を付け替えられる。
- インボイスの登録番号（T と 13 桁、未登録も可）と端数処理（切り捨て・四捨五入・切り上げ、初期値は切り捨て）。
- 価格は税込。1 回のお会計で税率ごとに対象額を合計してから 1 回だけ端数処理し、内税額を出す。0% を除く税率は明細がなくても常に表示する。

### 15.1 シミュレーターの配置

- 上部：ロゴ、「Janus POS」、ビルド番号、右端に「リセット」（3.4）。
- 左列：Bell（歯車で呼び鈴機能の設定）、レジごとに見出し（レジ番号・無操作の残り時間・スタッフのセレクタ）、スタッフ側とお客様側の画面、その下に入金・出金ボックス（スタッフ側）と、左に決済端末・右にスキャナ（お客様側）。
- 右列：Item（売り場の棚。歯車で販売規則の設定）と Wallet（お金・ポイントカード・ポイントアプリ・クーポン・バーコード決済・クレジットカード・電子マネーと残高）。受付済みの荷物の伝票（取り消し用）も Item に並ぶ。

- Item・Wallet のボタンにカーソルを重ねると、少し遅れて使い方を出す。
- 下部：著作権表示。

### 15.2 ビルド番号

`build:YYYYMMDDhhmm`（日本時間でビルドした日時。例 `build:202609032206`）。開発サーバーでは起動した日時。

### 15.3 レジ画面

- ヘッダー（高さ 51px）：左に稼働モード、中央にベル、右に日時（「2026年11月5日 木曜日 09:21」）。背景は普段は無色。呼び出し中だけ、中心（ベルのまわり）ほど濃く周辺へ消えていくやわらかい黄色で点滅し、ベルから来ていることを表す。
- 登録画面の上の帯：左から取引中止・合計（点数・金額、その下に小さくポイントの読み取り状況）・会計ボタン。明細がないときは出さない。点数が上限に達すると「上限」を添える。帯の高さは大ボタン（48px）に上下 8px の余白を足した 64px。
- 明細の表：品目｜数量｜小計。表の上に内税の内訳（スタッフ操作モードは担当スタッフ名も）。新しく動いた行を一瞬目立たせ、表を一番上まで戻す。
- 画面下：スタッフ操作モードのスタッフ側は FF のタブ、セルフ操作モードは呼び出しボタン。確認画面・店舗メニュー・電子マネーの手続き・荷物の取引中は出さない。
- レジ画面ではトーストやダイアログで覆い隠さない。例外は数量とテンキーのポップアップ、点数上限と販売個数の上限の警告。
- 受け付けなかった操作の理由は、覆わない表示で出す。レジに送って断られたコマンド（スキャン・FF の登録・決済端末にかざす・現金の投入など）の理由を、操作した側の画面（スキャンは読ませた側）の二段目の帯の直下、内税の行の位置に赤文字で出す（帯のない案内画面では画面の一番上）。何も覆わず、閉じるボタンも置かない。表示中もすべての操作を受け付け、異常音（ブッブー）は今までどおり鳴らす。そのレジで次に操作が受け付けられたとき、または 8 秒（web `REJECT_SHOW_MS`）で消え、新しい理由が来たら置き換える。英語の画面では英語で出す。荷物の入力欄・入力欄ひとつの画面のテンキーは、それぞれの場所に理由を出すので対象外。店舗メニュー・販売規則の設定は今までどおりトーストで出す。例：ソフトドリンクの後に「荷物を送る」の伝票を読むと「荷物の発送は、ほかの商品と一緒に会計できません（荷物どうしは何個でも一緒に会計できます）」
- スタッフ操作モードのお客様側は見るだけで、ボタンを押せない形で映す。
- 余白：レジ画面の中の部品の間隔・余白は 8px にそろえる（ボタン同士の間隔、帯・確認画面・案内・ポップアップの余白など）。登録画面の左右の 12px のように、8px とはっきり違う値はそのまま。

### 15.4 待ち受け

- セルフ操作モード：「バーコードをスキャンしてください／すべてのバーコードを受け付けます」と、案内ボタン 商品・レジ袋・ポイント・お支払い・クーポン。ボタンを押すと読むものの案内を出す（もう一度押すと閉じる）。押さなくてもどのバーコードも読める。
- スタッフ操作モード：スタッフ側に「お辞儀とご挨拶をしましょう／ご用件をお伺いしてください」、お客様側に「いらっしゃいませ／ご用件をお申し付けください」。案内ボタン お買い物・宅配便・お支払い（スタッフ側だけ押せる）。
- 案内ボタンは強い丸みのボタン。選択中のボタンは濃い背景・白文字・枠線なしで示す（下線は使わない）。ボタンで出すガイダンスは青文字。支払方法のボタンも画面遷移を伴わず案内を出すだけのボタンなので、案内ボタンと同じ強い丸みで、選択中は濃い背景・白文字・枠線なし。もう一度押すと選択を外す（セルフ操作モードの「現金」は店員呼び出しなので除く）。支払方法を選んだときに出すガイダンス（例：「Wallet の電子マネーを、決済端末にかざしてください」）も青文字。

### 15.5 文言

- 案内文は文末に「。」を付けない。
- 案内は一行目 18px（太字）、二行目 13px で、領域の上下左右の中央に置く。
- 一行目＝大きなテキスト（濃いグレー・太字）、二行目＝小さなテキスト（薄いグレー）。大きなテキストは必ず小さなテキストより上に、4px 空けて置く。アプリ全体で待ち受け画面と同じ表現にそろえる（web `msg()`）。青文字の案内、呼び出し画面の理由、数字の強調（荷物番号・残高・枚数）は対象外。
- 確認・案内画面の配置はすべて共通：大きなテキスト→小さなテキスト（4px）→ボタン（16px）を一つのまとまりにして領域の中央に置く。バック・閉じる・他の決済を使うなど引き返すボタンは左下の角、スキップなど先へ進む補助ボタンは右下の角。角のボタンの有無でまとまりの位置が変わらないよう、上下に同じ余白を取る。
- レジ画面の背景は稼働モードで色を変える：スタッフ操作モード＝ピンク（色相 330）、セルフ操作モード＝ミント（色相 150）。グレー・操作部品の青・注意の黄と、P・D・T 型の色覚でも見分けられる淡い色から選んだ。
- グラデーションは使わず、段ごとに塗り分ける。一段目（ヘッダー）と三段目は薄く（`oklch(0.95 0.035 330)`／`oklch(0.95 0.04 150)`）、二段目（待ち受けの帯・会計ボタンを含む帯）と四段目（FF・サイネージ）は濃いめ（`oklch(0.89 0.07 330)`／`oklch(0.89 0.08 150)`）。第一待ち受けも同じ塗り分け。操作する側と見るだけの側で背景は変えない（操作できる部品が青いことで区別する）。
- 第一待ち受け（有人レジ／セルフレジの特大表示）に戻るのは、取引のない待ち受けでレジ前に人がいない状態が30秒続いたときだけ。取引が始まってから完了するまで（ポイントカードだけ読んだ状態も含む）は決して戻らない。
- セルフ操作モードのスタッフ側（操作できない側）はモードの色を使わず、同じ塗り分けをグレーで行う（グレーアウト。薄い段＝`#d4d4d4` 45% を白に混ぜた色、濃いめの段＝`#d4d4d4`）。
- 呼び出し中のスタッフ側の画面は、エマージェンシーと同じやわらかい黄色（`--alert-bg`）を同じ塗り分けで使う（濃いめの段は `oklch(0.91 0.11 98)`）。
- 商品が登録された行を一瞬だけ染めるエフェクトも、濃いめの段と同じモードの色（ピンク／ミント）。

- タブ（FF のタブ、モバイルの画面切替）は、ボタンと形を分ける。上の角だけ丸め、下は一本の線に載せる（モバイルの画面切替は画面の枠に載せる）。押すと音は鳴るが、位置はずらさない。
- 進めるボタンは右、引き返すボタン（バック）は左下、本筋ではない前進（スキップ・セルフ操作モードの現金）は右下。左下は「この画面を出る」全般で、完了後の「閉じる」も左下。「他の決済を使う」は左下（セルフ操作モードの残高不足の二択だけは、勧める側として右の積極ボタン）。
- 形の意味：弱い角丸＝押すと何かが起きるボタン、強い丸み＝案内を出すだけの第三のボタン（選択中は濃い背景・白文字、下線は使わない）、角なし＝値を入れる入力欄。押せない情報（「2個目」「上限」、ポイントカードの絵など）はボタンの形にしない。
- グレーの意味：押せない。明細の削除・−・＋も操作できる側では青。例外は長押しの操作だけ：在庫無しの FF はグレーアウトだが、長押しで予約注文として登録できる。
- 青の意味：操作に関わるもの（操作できる部品と、ボタンを押したときに出す案内文）。
- 意味の色は文字と背景にだけ使い、ボタンには使わない（ボタンは青＝押せる、グレー＝押せない）。レジ画面でもグレーに置き換えない。
  - 黄＝人を呼ぶ・人に気付かせる（呼び出し中のヘッダー・背景、釣り銭の取り忘れ・エマージェンシーの背景、呼び鈴）。
  - オレンジ＝取引を止めているもの（フラグのある行、年確・期限切れ）。
  - レッド＝危険・否定・エラー（釣り銭の取り忘れ、エマージェンシー、照合の NG、入力エラー、枚数の不一致）。
  - グリーン＝安全・完了（照合の OK）。
- 画面はグレーで描き、操作できる画面の操作できる部品だけを青の濃淡に置き換える（SVG フィルター。色覚の違いでもグレーと見分けられる青）。色は OKLCH で定義する。
- 入金ボックス・決済端末は、受け付けている間は枠が点滅する（背景は塗らない）。スキャナは待機中は光らない。出金ボックスはお金がある間、枠と金額が点滅する。
- 読み取った瞬間の演出：スキャナは商品・決済用バーコード・ポイントカードを読むと濃いめの赤帯が左から右へ走る。レジ画面に商品を入れるのもスキャナを通したのと同じ扱い。ただしスタッフバーコード（ログイン・担当者の切り替え）では出さない。決済端末は電子マネー・クレジットカードをかざすと中心から青い光が広がる（色の濃さは赤帯と揃える）。

### 15.7 テンキー

- 数値は入力欄からテンキーで入れる（ボタンからは開かない）。離散値は選択肢から選ぶ。
- 対象：数量（2 桁）、三辺の合計（3 桁）、重さ（小数第 1 位まで）、郵便番号（7 桁、3 桁目の後にハイフンを表示）、生年月日（8 桁）、お渡し数（3 桁）、入金（6 桁）、出金額（6 桁）、店舗パスワード（8 桁、●表示）。
- 左下「バック」でやめ、右下「決定」で入れる。外側を押してもやめる。キーボードの数字・小数点・Backspace・Enter・Esc でも打てる。
- 入力欄が画面から消えたらテンキーを閉じる。出金の画面を離れたら、入れかけの金額とパスワードを消す。

### 15.8 音

| 音 | とき |
| --- | --- |
| 「ピッ」 | スキャン・FF の登録・スキャナで読んだものが受け付けられた |
| 「シャーン」 | 決済端末で電子マネー・クレジットカードの支払いが受け付けられた |
| 「ブッブー」 | 同じ操作が受け付けられなかった |
| 「コッ」 | ボタンを押した |
| 呼び出し音 | Bell が鳴っている間、0.5 秒ごとに繰り返す |

音は Web Audio で合成し、最初の操作で準備する。

### 15.9 モバイル（幅 760px 以下）

- Item・Wallet の欄は出さない。長押し（0.5 秒）で選ぶ画面が開き、タップで選ぶ。デスクトップの「レジ画面＝スキャナ」をそのまま写し、レジ画面の長押しは Item を上・Wallet を下に、スキャナの長押しは Wallet を上・Item を下に両方並べる。入金ボックス（現金）・決済端末（かざす）の長押しは Wallet だけ。選んだものの扱いはドラッグ＆ドロップと同じ（決済端末は電子マネー・クレジットカードだけ、スキャナはバーコードとポイントカードだけ、現金はスタッフ側だけ）。
- スタッフ側とお客様側はスワイプかタブで切り替える。タブは FF のタブと同じ形で、表にしている面が積極タブ（幅 2/3）、もう一方が消極タブ（幅 1/3）。操作する面が変わると、その面を表にする（セルフ操作モードはお客様側、スタッフ操作モードと店舗メニューはスタッフ側）。タブも操作できる面だけ青にする。
- 入金・出金ボックスはスタッフ側、決済端末・スキャナはお客様側を見ているときだけ出す。
- 最下段の呼び出しボタンの添え字（「揚げ物・中華まん」など）は表示エリアが狭いので出さない。表示エリアの制約による妥協で、実機では出す。待ち受けの帯の言語・電子マネーは大きさに余裕があり、「電子マネー」だけだと決済のボタンと間違えやすいので、添え字を出す。

## 16. 時間の定数

| 名前 | 値 | 意味 |
| --- | --- | --- |
| `TOUCH_LOCK_MS` | 1 秒 | 操作した側だけが操作できる時間 |
| `THANKS_MS` | 3 秒 | 決済後のお礼の画面 |
| `INSERT_DONE_MS` | 30 秒 | 無投入で投入おわりとみなす |
| `IDLE_REVERT_MS` | 5 分 | 無操作でセルフ操作モードに戻る |
| `CHANGE_REMIND_MS` / `STAFF_OP_…` | 1 分 / 30 秒 | 釣り銭が残っていますの表示 |
| `CHANGE_CALL_MS` / `STAFF_OP_…` | 2 分 / 1 分 | 釣銭忘れの呼び出し |
| `RING_FULL_MS` | 60 秒 | 呼び出しの音量・色が最大になる放置時間 |
| `LOCKOUT_MS` | 30 秒 | パスワードの連続失敗のロック |
| `EMERGENCY_UNANSWERED_MS` | 5 分 | 応答のない呼び出しで非常事態モードに入る（11.4） |
| `EMERGENCY_LOG_MS` | 10 秒 | 非常事態モードの解除のレシートの案内 |
| Bell の再送・ハートビート・不通 | 200ms / 2 秒 / 5 秒 | 11.3 |

## 17. コマンド

コアに送るコマンドは `{"type": "...", ...}` の JSON。結果は `{"ok": true, "message": ...}` か `{"ok": false, "error": "..."}`。レジに関わるコマンドは、成否にかかわらずそのレジの無操作の時刻を更新する。

| 分類 | コマンド |
| --- | --- |
| 登録 | `scan`・`register_ff`・`ff_button`・`check_ff`・`remove_line`・`set_qty`・`remove_coupon`・`dismiss_returned` |
| サービス | `complete_service`・`parcel_length`・`parcel_size`・`parcel_postal`・`parcel_back`・`parcel_next`・`pickup_found`・`pickup_handover`・`check_bill`・`hand_over_bills` |
| 会計 | `checkout`・`back_to_registering`・`confirm_point_card`・`choose_age_check`・`check_id`・`dismiss_confiscated`・`dismiss_ff_collect`・`select_payment` |
| 支払い | `insert`（金額）・`insert_cash`（金種と枚数）・`finish_insert`・`tap_emoney`・`take_outlet` |
| 電子マネー | `start_emoney`・`close_emoney`・`resolve_emoney_short` |
| 呼び出し | `call_staff`・`release_call`・`end_emergency` |
| レジ | `void_transaction`・`end_staff_mode`・`pause`・`claim` |
| 店舗メニュー | `open_menu`・`cash_out`・`cash_in` |
| 販売規則 | `verify_owner`・`add_age_rule`・`remove_age_rule`・`set_product_age`・`set_sale_limit`・`set_tax_rate`・`add_tax_class`・`set_product_tax`・`set_invoice` |
| Bell | `set_bell_loss`・`set_bell_offline`・`set_bell_on` |

スナップショットは、レジごとのビュー（スタッフ側・お客様側・操作の可否と理由・使えない支払方法など）、Bell の状態、呼び出しと履歴、年確ルールと変更履歴、監査ログ、FF の在庫、スタッフ、商品、税設定、電子マネーの残高を持つ。お客様側のビューには商品コード・分類を載せない。

## 18. 開発

```sh
bash scripts/install-wasm-pack.sh
cd pos
npm install
npm run build:wasm
npm run dev
npm test
npm run build
(cd core && cargo test)
```

- CI（`.github/workflows/ci.yml`）は push（main）と PR で cargo test・WASM のビルド・Vitest・型検査とビルドを行う。
- `main` への push で GitHub Pages に `pos/dist` を公開する（`.github/workflows/pages.yml`）。
- コアの業務ルールのシナリオテストは `pos/core/tests/scenarios.rs`。
