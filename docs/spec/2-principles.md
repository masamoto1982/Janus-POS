# 第二階層　Janus-POS の原則

実機としての Janus-POS が守る原則。第三階層の各場面はこの番号で根拠を示す。新しい画面をつくるときは、まずここに照らす。

「（提案・未確認）」と付けたルールは、これまでの決定から読み取った案で、まだ確定していない。

## 大原則

- **P-01 機械の都合を押し付けない**：機械の都合を顧客やスタッフに押し付けない。すべての操作はやりたいときにできる。新しい操作の入口は、待ち受け・登録中・会計中・確認中のどこからでも始められるかを確かめる。
  - 例：有人モードで会計の途中に電子マネーのチャージを頼まれても、取引を終えて待ち受けに戻らずにできる。
- **P-02 仕組みはシンプルに**：人がついていけない機能は入れない。取引保留・画面ロックは持たない。モードは有人とセミセルフの二つだけ。

## モードと画面の役割

- **P-03 モードはログインで決まる**：スタッフバーコードでログインしていれば有人、していなければセミセルフ。ログアウトか、取引がなく 5 分間操作がないときにセミセルフへ戻る。
- **P-04 二つの画面は同じ取引の見え方**：スタッフ側と顧客側は一つの取引状態を二方向から見たもの。どちらかにしかない状態をつくらない。
- **P-05 操作する側**：有人モードではスタッフ側で操作する。顧客側に出すボタンはお客様本人が押すもの（「投入おわり」、FF の「確認しました」）だけで、ほかは表示だけ。セミセルフモードでは顧客側で操作し、スタッフ側はスタッフがログインして対応するときに使う。
- **P-06 片側だけのボタン**：「投入おわり」は例外なく顧客側だけ（入れ終わったかはお客様にしか分からない）。有人モードの FF のお受け取りの「確認しました」も顧客側だけ。年確の選択・身分証の生年月日入力・払込票の確認とお渡しはスタッフ側だけ。新しく加えるときは core の `is_customer_only` / `is_staff_only` に登録する。
- **P-07 対のメッセージ**：確認の最中は、操作しない側に、操作している側と対になる短いメッセージを出す（例：スタッフ側「取引を中止しますか？」⇔ 顧客側「取引の中止を確認しています」）。お客様に「没収」などの強い言葉は見せない。
  - 例：スタッフ側が FF のお渡しの確認・回収をしている間、顧客側にはお受け取り・お返しの案内を出す。スタッフ側ほど厳格にせず、右下の積極ボタン「確認しました」で済ませられる。
  - FF のお受け取りは相互チェックにする：顧客側の「確認しました」はスタッフ側の照合が済んでから押せ、会計には両方の確認が要る。FF を足したり個数を変えたりしたら、両方とも確かめ直す。

## 一画面一確認

- **P-08 確認は登録画面を置き換える**：確認画面は登録画面（FF タブを含む）を置き換える。両方を同時に出さない。確認画面は登録領域の上下左右とも中央に置く。
- **P-09 一つの画面で一つの確認**：複数の確認を一度に出さない。後の確認は前の確認が済むまで待たせる。優先順は次のとおり。
  1. 取引中止の確認（どの場面からでも）
  2. 荷物を受取る・荷物を送るの受付
  3. 公共料金の払込票の確認（受付で即座に）
  4. 年齢確認
  5. 販売不可商品の回収・FF の回収・クーポンの照合と返却
  6. ポイントカードの最終確認
  7. 決済手段
- **P-10 同じ情報を二か所に出さない**：一つの画面で同じ情報を二度出さない。点数・合計は上の帯、投入額は入金ボックス、選んだ決済手段はボタンの強調で示す。ほかにない情報（「あと N円 入れてください」など）だけを本文に出す。

## 常設部分

- **P-11 ヘッダーは常に出す**：モードバッジ（左）・日時（中央）・呼び鈴（右）は、どの場面でも出す。
- **P-12 上の帯**：点数・合計とその右の会計ボタンは登録画面の最上部に固定し、明細が増えても隠れない。何も登録していないときは出さない。点数・合計は呼び出し中と確認中を除いて両方の画面に出す。
- **P-13 覆いかぶさる表示をしない**：レジ画面にポップアップ・トーストを出さない。知らせは画面の中に出す。

## テキスト

- **P-14 積極テキストと消極テキスト**：画面の文はどちらかに分ける。積極テキストは濃い色（#535353）で大きく、消極テキストは薄い色（#878787）で小さい。積極テキストは必ず消極テキストより大きい。
- **P-15 一場面の積極テキストは一つ**（提案・未確認）：一つの確認画面で主に伝えることは一文にする。補足は消極テキストに回す。
- **P-27 スタッフという呼び名**：店員・係員などを使わず「スタッフ」に統一する。画面の呼び名も「スタッフ側」「顧客側」とする。ログインは「スタッフバーコードでログイン」と言う。
- **P-16 お客様への言葉**（提案・未確認）：顧客側は敬語で、スタッフへの指示を見せない。スタッフ側は次にすべき行動を書く（例：スタッフ側「決済手段をお伺いしてください」⇔ 顧客側「決済手段をお申しつけください」）。
- **P-17 「スキップ」の意味**：「スキップ」は手順を省いて前に進むときだけ使う。手続きをやめて元に戻るボタンは「〜をやめる」「〜に戻る」とし、引き返すボタンとして扱う。

## ボタン

- **P-18 積極ボタンと消極ボタン**：積極ボタンは濃い背景・白い文字・枠なし。消極ボタンは濃い枠と濃い文字・背景なし。ボタンは既定で積極にする。スキップ・やめる・戻る・閉じる、および切り替えボタン（タブ・決済手段）の選ばれていない側は消極。選ばれた側は積極になる。
  - 積極ボタンは消極ボタンと必ずしも対にならない。勧めたい選択肢があるときは、それを積極、もう一方を消極にする（例：年確は「する」が積極、「スキップ」が消極。リスク管理の観点から年確を勧める）。どちらを選んでもよい選択肢は、積極ボタンを並べる（例：荷物の受付の「次の荷物はありますか？」の「ある」「ない」）。
  - 消極ボタン同士を並べない（不自然なため）。
  - 例：明細の数量そのものが積極ボタンで、押すと最下段がテンキーになり、新しい数量を打ち込む（左下「やめる」、右下「1 文字消す」「決定」）。数量の両脇の「−」「＋」は消極ボタンで、押すとその場で 1 つずつ変わる。数量が 1 のときの「−」は「削除」になる。数量を変えられないもの（サービス商品・クーポン）は「削除」と数字だけ。
- **P-19 進むは右、戻るは左**：手続きを進めるボタンは右に、手続きを引き返すボタンは左に置く。確認画面で引き返すボタンが一つだけなら左下に置く（人は右へ進むと感じるため）。例外はない。
  - 会計ボタンを、会計中に引き返すボタンに置き換えない。会計中の「商品登録に戻る」は確認画面の左下に置く。
  - やめる・閉じるも引き返すボタンとして左に置く。
- **P-20 取引中止は誤操作させない**：取引中止は会計ボタンから離した控えめなボタンにし、確認画面では「続ける」を既定とし、「長押しで中止」を押し続けたときだけ中止する。
- **P-21 押せない理由**：押せないボタンには、押せない理由を示す（core の `reason`）。

## 色と形

- **P-22 画面は四つのグレー**：画面の色は #535353（選択・積極テキスト）、#878787（枠・消極テキスト）、#AEAEAE（ボタン）、#D4D4D4（帯・淡い塗り・無効）と白黒だけ。これ以上グレーを増やさない。
- **P-23 操作できる部品だけ青**：その画面で操作できる部品（ボタン・入力欄・モードバッジ）だけを色覚に配慮した青の階調で塗る。テキスト・表・知らせ・売り切れなどの無効な部品・反対側の画面でしか押せない部品はグレーのまま。
- **P-24 枠の意味**：枠が破線になる＝ここで操作を受け付ける。枠が点滅する＝注意（例：お釣りの残った出金ボックス、決済手段を選んだ後の入金ボックス）。
- **P-25 明細の列**：明細は品目・数量・小計の三列。年確・限定・現金のみの印は品名の横に、四角い枠と消極テキストの色で出す。数量はボタンで、押すとテンキーで新しい数量を打ち込む。数量の両脇に「−」（数量 1 では「削除」）と「＋」を置き、押すとその場で数量が変わる。数量を変えた行は並びを変えない（押した行が動くと、続けて押すときに取り違えるため）。
- **P-26 横スクロールしない**：レジ画面は横にスクロールさせない。長い文言は折り返すか行を分ける。幅 1024 / 1280 / 1366 / 1920 で確かめる。
