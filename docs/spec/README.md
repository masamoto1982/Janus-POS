# Janus-POS 画面仕様書

Janus-POS の画面の決まりごとを三つの階層に分けてまとめる。上の階層が下の階層を縛る。

| 階層 | ファイル | 中身 | ルール番号 |
| --- | --- | --- | --- |
| 一 シミュレーター仕様 | [1-simulator.md](1-simulator.md) | 実機には存在せず、シミュレーターだから持っているもの | S-xx |
| 二 Janus-POS の原則 | [2-principles.md](2-principles.md) | 実機としての Janus-POS が守る原則（積極／消極、ボタンの向きなど） | P-xx |
| 三 スタッフ側／顧客側の対表 | [3-screens.md](3-screens.md)（正本は `3-screens.ts`） | 場面ごとに、両側の積極・消極テキストとボタン | 場面ID |

## 運用

- 画面・文言・ボタンを変える PR は、同じ PR で仕様書も直す。
- ルール番号は一度振ったら使い回さない。廃止したルールは「廃止」と書いて番号を残す。
- 第三階層の各場面は、従うルールを番号で示す。ルールを変えたときは番号で影響する場面を探す。
- 第三階層は仕様の正本をデータ（`3-screens.ts`）で持ち、読むための表 `3-screens.md` はそこから生成する。データを直したら `pos` で `npx vitest run -u` を実行して表を書き直す。表が古いままだと CI（`pos/web/src/spec.test.ts`）が落ちる。
- 描画した画面とデータを照合するテストは、次の段階で加える。

## 用語

- スタッフ側／顧客側：一台のレジにある二つの画面。お客様側の画面の下に入金ボックス・出金ボックスがある。
- 有人モード／セミセルフモード：スタッフバーコードでログインしていれば有人、していなければセミセルフ。完全セルフモードはない。
- 場面：モード × 手続きの段階 × そのとき出ている確認ごと。第三階層の対の単位。
- 常設部分：ヘッダー（モードバッジ・日時・呼び鈴）と、登録画面の最上部の帯（点数・合計・会計など）。
- 本体：登録画面、またはそれを置き換える確認画面。
